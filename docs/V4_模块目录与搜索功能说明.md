## 二、这 178 个模块是从哪来的

### 采集过程

1. **源**：社区维护的 `awesome-android-root` 精选清单，抓了 **6 个 fork**（`Byron538`、`dengyisheng`、`eomdohyeon`、`fibonacciscot`、`TheeGodFather`、以及 awesome-android-root 本体）。
2. **解析**：清单里 `- **[名称](url)** - 说明 \`FOSS\` \`[M]\`` 这种固定格式，共 1621 个条目行，成功解析 **1605** 行（漏掉的 16 行是站内相对链接、纯 App、或用 `–` 而非 `-` 分隔的个例）。
3. **筛选**：只保留标了 `[M]`（Magisk/KSU 模块）的条目 → **162 个模块**，其中 153 个带 `FOSS` 开源标记。
4. **去重合并**：与原来人工整理的 40 个（以 Root 隐藏 / 完整性为主，含金量最高）查重，跳过 7 个重复项，新增 **135** 个。
5. **补 KPM**：加上 KernelPatch 官方仓库 `bmax121/KernelPatch` 里的 3 个示例 KPM。

```
原有 40  +  新增 135（去重跳过 7）  +  KPM 示例 3  =  178
```

6. **验证**：批量访问每个仓库的 releases 页，145 个确认返回 200/302（有发布页）。剩下 23 个返回 403，是 GitHub 镜像限流，不是仓库消失——复检时也全部是 403，判定为镜像抖动，予以保留。

### 收录规则

- **必须是开源仓库**。这是你提的硬条件，清单里的 `FOSS` 标记是主要依据，非开源的一律不收。
- **不做二次打包**，全部走 GitHub Releases 直链，版本列表实时从 GitHub API 拉。
- **不收"格机"类**——准确说，这个目录里没有任何会格机的东西。模块是 systemless 覆盖，**刷错了最坏是开机卡 MIUI/one logo 或进安全模式，进 Recovery 删掉模块目录即恢复**，不存在格机。真正会格机的是刷错分区镜像（boot/dtbo/vendor_boot），那不在模块目录的范围内。

### 主动排除的 3 个

这三个在精选清单里也标了 `FOSS`，但我没放进目录，理由是**它们不是"玩机"而是攻击/盗版工具**：

| 排除项 | 原因 |
|---|---|
| `DriFiCrack` | Wi-Fi 密码破解 |
| `EDS-NG-crack` | 付费应用授权破解 |
| `JustTrustMePro` | 全局关闭 SSL 证书校验（把自己置于中间人攻击之下） |

如果你确实需要它们，把它们手工加回 `module_repo.json` 即可，格式照抄任意一条。

## 三、KPM 为什么只有 8 个（这点得跟你说实话）

你要「网络上出现的所有 KPM」，我全找了，**开源 KPM 的生态就是这么小**：

| 名称 | 来源 |
|---|---|
| `KernelPatch 示例：hello` | `bmax121/KernelPatch` 官方示例 |
| `KernelPatch 示例：inlinehook` | 同上 |
| `KernelPatch 示例：syscallhook` | 同上 |
| `re_kernel` | 随 KernelPatch 分发的实用 KPM |
| `hosts_redirect` | 同上 |
| `critical_partition_protect` | 同上 |
| `selinux_policydb_fix` | 同上 |
| `memagent` | 同上 |

原因是**结构性**的，不是我没找到：

- KPM 是 **KernelPatch / APatch** 专用的内核态 ELF，由 KernelPatch 在内核里加载。能用它的前提是你的内核已经被 KP 打过补丁。
- 写 KPM 要对着内核符号表编程，**每个内核版本、每个机型都不通用**，所以作者没有动力公开发布——发了别人也刷不上，刷错就是变砖。
- 结果就是：**公开的 KPM 基本只剩官方 demo 和几个通用小工具**。真正好用的 KPM（比如隐藏 KP 自身、绕过某家银行的检测）都以闭源形式在小圈子里流传，这些不可能收进一个开源目录。

如果你想要更多 KPM，现实路径是：用 `KernelPatch` 的 `kptools` 自己把想要的 hook 编进去，或者去 APatch 的 KPM 板块找闭源发布。塞一堆搜不到、刷不上的假条目进目录只会让搜索变垃圾。

## 四、搜索功能怎么用

在「模块下载中心」顶部新增了一行搜索框（沿用原有的 iOS 玻璃卡片风格 `bg_search_box`，没有引入新的视觉语言）。

- **实时过滤**：每敲一个字就地过滤，纯内存操作，不发网络请求。
- **匹配范围**：模块名、作者、`owner/repo` 仓库全名、分类、说明文字、内部 id。
  → 所以你可以直接搜 `j-hc`（某个作者的所有模块）、`zygisk`、`完整性`、`字体`、`KPM`。
- **多关键词 AND**：用空格分隔，全部命中才显示。比如 `j-hc zygisk` 只出 Zygisk Detach。
- **大小写不敏感**，`HTTPS` 和 `https` 一样。
- **与筛选芯片联动**：先选「KPM 内核模块」再搜 `hook`，就是在 KPM 里找。
- 右边有 **× 清空**按钮（有输入时才出现）。
- 搜索框下方显示 `共 178 个模块` 或 `匹配 12 / 178 个模块`。

实现在 `ModuleRepoActivity`：

```java
/** 搜索框切成小写关键词，全部命中才算匹配（AND）。 */
private String[] queryKeys() { ... }

/**
 * 每个条目拼一个"稻草堆"：名称 + 作者 + owner + repo + 分组 + 说明 + id。
 * 把 repo 全名也放进来的原因是：多数人记得的是 "j-hc/zygisk-detach"，不是显示名。
 */
private static boolean matches(ModuleEntry entry, String[] keys) { ... }
```

## 七、已知限制

1. **部分模块没有 Release 产物**：目录里的条目都来自精选清单，但个别作者只在仓库里放源码、不发 Release。点进去会提示"没有可用版本"，不是软件坏了。
2. **KPM 生态天花板**：见第三节，开源 KPM 就是这么少。
3. **清单可远程更新**：`ModuleRepoActivity` 里的 `CATALOG_URL` 指向仓库 raw 文件，你在自己仓库维护一份 JSON，App 里点"刷新清单"就能不升级 APK 更新目录；拉不到时自动回退内置清单。
4. **版本选择逻辑未变**：点条目 = 选版本（默认选中第 0 项即最新版），点"下载最新" = 直接拉最新。这是你最早提的"不选就是最新"规则。
