## 一、你提的两件事

### 1）「可刷入的文件」缺删除按钮

**问题**：KPM 刷写页里，从「选择文件刷入」导进来、或者躺在 Download 里的 `.kpm`，卡片上只有「刷入」一个按钮。想清理只能自己开文件管理器去找，很别扭。

**改法**：只有「可刷入的文件」这一类卡片出现「删除」（红色），已刷入和已嵌入的两种走各自原有的「卸载 / 移除」，语义不混。

| 卡片类型 | 按钮组 |
| --- | --- |
| 可刷入的文件（磁盘上的 `.kpm`） | 删除 · **刷入** |
| 已刷入（`/data/adb/ap/kpm/`） | 卸载 · 禁用/启用 |
| 已嵌入（boot 镜像内） | 移除 · **导出** |

删除前会弹确认框，**把完整路径原样列出来**——这是真删文件，没有回收站：

```
将从磁盘删除：

/storage/emulated/0/Download/VioletBox/Nohello.kpm

只删除这个 .kpm 文件，已经刷进 /data/adb/ap/kpm/ 的模块不受影响。
```

**删除走两条路**：
1. 文件在 app 私有目录（`Android/data/com.violet.box/files/Download/...`）→ 直接 `File.delete()`，不需要 root；
2. 在公共 Download 目录 → 需要 root，走 `KpmShell.deleteFile()`。

`deleteFile()` 做了三重防护：路径为空拒绝、路径以 `/` 结尾（目录）拒绝、`su` 侧再用 `[ -d ]` 判一次目录后拒绝。绝不接受 `rm -rf` 一个目录。

### 2）运行环境默认展开一次，之后记忆折叠

**你要的行为**：第一次用这个页面，运行环境是展开的；用户之后把它收起来，再进这个页面就该是收起的，点「运行环境」几个字才重新展开。

**实现**：`SharedPreferences("kpm_manager").getBoolean("env_expanded", true)`

- 默认值 `true` → **首次进入必定展开**，符合你的要求
- 用户点标题行 → 状态取反并立刻落盘（`apply()`），下次进来读同一份值
- 整块标题行（含右侧按钮）都是点击热区，不用去戳那个小按钮

#### 顺手加的一点：折叠时留一行摘要

折叠之后如果卡片只剩「运行环境」四个字，用户每次想知道 APatch 版本都得点开一次，反而更烦。所以折叠态会在标题右边显示一行灰色摘要：

```
运行环境          ROOT 已获取 · APatch 115028        [展开]
```

摘要由已经拿到的检测文本拼出来，不额外跑任何 shell。反过来说，**展开 / 折叠这个动作本身零 I/O、零 root 调用**，不会让页面卡一下。

## 二、修复「重新打补丁失败」（kpimg 从未被刻出）

这是实测嵌入时撞上的真 bug，不是猜测。现象是：

- `dd` 导出 boot 成功（`DUMP_RC=0`）
- `kptools unpack` 成功，识别出 GZIP、解出 51MB kernel
- `[kernch] patched=true`，superkey 相关字段也读到了
- 然后 `kptools -p` 直接失败 → 弹窗只报一句「重新打补丁失败，未做任何刷写。详情见日志。」

**根因**：`KpmEmbedTool.inspect()` 里写的是

```java
st.preset = KpmPreset.scan(in, null);   // ← 第二个参数是 kpimg 的输出流
```

传了 `null`，意味着 **`kpimg` 这个 blob 从来没有被写出来过**。而 `patch()` 里的命令却是

```
kptools -p -i kernel.ori -S violetbox -k kpimg -o kernel ...
```

`-k kpimg` 指向一个磁盘上根本不存在的文件。kptools 拿到空/缺失的 kpimg 就非零退出，于是报了那句等于什么都没说的错。

**改法**：`inspect()` 在识别 patch 的同时把 kpimg 刻出来。

1. 先刻到 app 自己的缓存目录（`WORK = /data/local/tmp/violetbox_embed` 是 root 建的，app 身份写不进去）；
2. 再用 `KpmShell.writePrivileged()`（`su -c "cat > path"`）送进工作目录 —— 和暂存 `.kpm` 走的是同一条通道；
3. 刻出失败、落盘后 0 字节，都明确记进日志并换下一个分区，而不是带着空文件往下走；
4. `patch()` 开头再补一道闸门：kpimg 不可读就直接报「缺少 kpimg 载体」，不再让 kptools 用一句无意义的话糊弄过去。

日志里现在会多一行，可以据此确认修复生效：

```
# 已提取 kpimg：1234567 字节
```

## 三、日志支持一键复制

日志是排查这类问题的唯一线索，之前只能瞪着屏幕看，还不能选全（对话框里长文本很难操作）。

- 日志弹窗底部加 **「复制日志」**，剪贴板拿到的是**完整**日志，不是屏幕上被截断的那 8000 字符
- 截断从**头部**切、保留尾部（错误通常在最后），并在开头说明「用「复制日志」可拿到完整内容」
- 失败弹窗上直接多一个 **「复制日志」** 按钮，不用先点「查看日志」再点一次
- 复制成功后 Toast 会带上字符数，方便确认拿到的是全量

### 一处细节：为什么删除按钮用 `GONE` 而不是每次 `bind` 重建

`RowHolder` 是复用的，所以 `bind()` 开头先把 `btnDeleteFile` 置为 `GONE`，只有「未刷入且路径以 `.kpm` 结尾」才放出来。
否则滚动列表时，一个已刷入的模块复用到了刚才那个文件行的 View，就会莫名其妙冒出一个删除按钮。
