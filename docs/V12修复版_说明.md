## 一、你这次提的四个问题，逐条对应

### 1. 为什么不能后台下载 → 现在可以了

原来的下载框写着「请勿退出当前页面」，是因为对话框用了 `setCancelable(false)`，一退出页面任务就跟着废掉。改法：

| 改动 | 说明 |
|---|---|
| `setCancelable(true)` | 按返回键 / 点空白处只关界面，**不停任务** |
| 两个按钮 | 「后台下载」= 关界面继续下；「取消下载」= 才真的 `call.cancel()` |
| 提示语 | 「正在下载，请勿退出当前页面」→ **「可离开本页面，下载会在后台继续」** |
| 通知栏兜底 | 新建 `violet_download` 低优先级通道，进度实时同步到通知栏；完成/失败也在通知栏给结果 |
| Android 13+ | 自动申请 `POST_NOTIFICATIONS`，不给也能下，只是看不到通知 |

### 2. 文件必须存到 `/storage/emulated/0/Download/VioletBox` → 全部统一

| 场景 | 路径 |
|---|---|
| 模块下载（ZIP / KPM / LSP） | `/storage/emulated/0/Download/VioletBox/` |
| 模块备份 | `…/VioletBox/备份/ZIP模块`、`…/VioletBox/备份/内核模块` |
| APK 导出 | `…/VioletBox/apk` |
| 应用备份 | `…/VioletBox/应用备份` |

**这里有个坑必须说清楚**：应用 `targetSdk = 36`，Android 11+ 的分区存储**禁止应用直接写 `/storage/emulated/0/Download`**，原写法 `Environment.getExternalStorageDirectory()` 会静默失败、退回私有目录（卸载即丢）。所以做了三级递进：

1. 公共目录可写（已授予「所有文件访问权限」）→ 直接写
2. 不可写但已 root → `su -c mkdir -p && chmod 777` 后再试
3. 仍不行 → 先下到私有目录，完成后用 `su -c cp` 搬到公共目录

同时在 `AndroidManifest.xml` 加了 `MANAGE_EXTERNAL_STORAGE` + `requestLegacyExternalStorage`，进模块下载页时若检测到写不进去会弹一次引导（已 root 的设备一般自动走通，不需要手动授权）。

新增文件：`app/src/main/java/com/violet/box/core/util/VioletPaths.java`（路径中心，下载/备份/导出都走它）。

### 3. 数量显示写死成 814 → 改成跟分类联动

原来的 `countText()` 把「全库总数」当成第二行固定输出。现在只显示**当前选中分类**的数量：

- 切到 ZIP → `ZIP 模块 1687 个`

- 切到 KPM → `KPM 内核模块 47 个`
- 搜索时 → `LSP 模块 2087 个 · 匹配 12 个`

## 二、这一轮新找模块的办法

### 1. 换排序突破 GitHub 的 1000 条上限

GitHub 搜索每个查询最多只能翻到 1000 条，所以同一个关键词换个排序就是不同的 1000 条。用 `filename:module.prop`（总命中 11584）、`filename:xposed_init`（总命中 3384）各跑 4 种排序，采集到 **1528 个仓库、其中 1089 个此前没收录**，逐个查 releases + 源码标记后新增 115 条（LSP 81 / ZIP 34）。

### 2. 镜像组织挖到底

| 组织 | 公有仓库 | 已收录 |
|---|---|---|
| Xposed-Modules-Repo | 1104 | 1026 |
| Magisk-Modules-Alt-Repo | 143 | 69 |
| Magisk-Modules-Repo | 100 | 26 |

剩下的 **227 个全部没有 release 产物**（有的只是源码仓库，没有编译好的 zip/apk），确认不是漏抓。

### 3. 多平台：试了 5 个，只有 GitHub + GitLab 可用

| 平台 | 结果 |
|---|---|
| **GitLab** | ✅ 可用，收录 15 条，逐个验证后保留 **11** 条 |
| Gitee | ❌ API `/search/repositories` 匿名返回空数组，网页端反爬 |
| Bitbucket | ❌ 搜索接口已下线（HTTP 410 `CHANGE-2770 deprecated`） |
| Codeberg | ❌ 对本机 IP 限流后直接封禁（429 → IP blocked） |
| SourceForge | ❌ 无公开搜索 API（HTTP 403） |

不是不想找，是这些平台在沙箱环境里取不到数据 —— 换台网络环境的机器重跑脚本就能补。

### 4. 剔除的假 KPM

新搜到 4 个「KPM」（`KPatch-Next-EXP`、`KernelPatchLite`、`kkpss`、`KernelPatch1`），查了产物发现都是 **KernelPatch 的 fork**，release 里躺的是同一套 `demo-hello/inlinehook/syscallhook.kpm`（早已收录），是框架不是模块，已剔除。

顺手修掉两个数据 bug：
- 去重规则按「仓库」去重，误删了 9 条**同一仓库的多个不同产物**（`bmax121/KernelPatch` 的 3 个示例、`lzghzr/APatch_kpm` 的 4 个、`geekbyter/dirtysepolicy_kpm` 等），已全部恢复
- 删掉 4 条实际下不动的 GitLab 条目（2 个是过期的 CI 产物 404，1 个产物挂在 mega.nz，1 个是 GitHub 仓库的重复镜像）

## 三、开源与安全口径（按你的定义执行）

> **有公开源码 + 源码里没有格机或破坏性代码 = 开源**，不要求 LICENSE 文件。

- 危险词用整词匹配 `\b(wipe|wipes|wiping|format|erase|nuke|brick)\b`，白名单放行 `swipe` / `Killer` / `brick guardian`
- 中文危险词：格机、清数据、恢复出厂、格式化手机、变砖
- 框架/工具一律不算模块：`LSPosed`、`LSPatch`、`VirtualXposed`、`EdXposed`、`SandHook`、`LSPlant`、`Vector`、`NeoZygisk`、`KernelPatch` 各 fork、`Magisk` 本体等

统计：官方（原作者仓库）**2700** 条 / 镜像 **1121** 条，卡片上官方用**蓝色小字**、镜像用灰色并标出原作者。
